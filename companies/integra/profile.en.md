## C. Business model and purchasing

**INFERENCE:** likely revenue streams are project implementation, recurring managed operations and vendor subscriptions/resale where contractually authorized. The support packages substantiate recurring service packaging; the professional-services catalogue substantiates scoped implementation. They do not establish margins, revenue or reseller rights for a third party. Buyers should request separate line items for consulting, software/subscriptions, cloud consumption, observability, support and change requests. [IN08](https://www.integratech.ae/aws-msp-program/) [IN14](https://www.integratech.ae/cloud-professional-services/).

**PROPOSAL:** procurement should select an accountable prime contractor and a precise handover point. A funded proof of concept still needs an exit plan, ownership of generated code, deployment access and a recurring-cost forecast. Request funding eligibility in writing; do not assume AWS credits or a free implementation are universally available. The relevant published offer is invitation-based. [IN09](https://www.integratech.ae/aws-genai-sdlc-iskaan-case-study/).

## G. Security, privacy and governance

The published website privacy statement concerns voluntary website submissions, communications, cookies and general safeguards. It is not a customer-workload DPA. A service-data retention schedule, complete subprocessor register, audit report and certificate scope/expiry were not established in this review. Framework-alignment language in managed services is not proof that the whole company or a particular workload is certified. [IN25](https://www.integratech.ae/privacy-statement-terms-of-use/) [IN08](https://www.integratech.ae/aws-msp-program/).

**FACT about AWS, not Integra:** Bedrock's documentation separates model-provider access from AWS processing. Current retention documentation is model/mode dependent and discusses possible retention/review and cross-region destinations. Therefore neither customer-account deployment nor Bedrock use proves universal zero retention, no training, or UAE-only handling across prompts, traces and support access. [IN26](https://docs.aws.amazon.com/bedrock/latest/userguide/data-protection.html) [IN27](https://docs.aws.amazon.com/bedrock/latest/userguide/data-retention.html).

**PROPOSAL — procurement gates:** obtain the data-flow diagram and region per component; enumerate model IDs, inference routing, logging destinations and retention; specify deletion evidence, training restrictions and backup exceptions; agree staff/subcontractor access and incident notification; verify certifications against legal entity and scope. Security-sensitive production access should wait for these answers. This is a due-diligence sequence, not a legal conclusion.

## I. Improvement hypotheses

These are **PROPOSALS**, not defect allegations. Existing tracing, roles and integrations should be reused after demonstration.

1. **Agent discovery:** broad agent promotion → buyers may struggle to identify deployable scope → publish a versioned catalogue and dependency checklist → validate with five buyer task selections → depends on product ownership → pass if all selected agents have named inputs, actions, region and support owner. [IN03](https://www.integratech.ae/)
2. **Integration acceptance:** workflow integrations are described → compatibility gaps may emerge in each customer stack → add contract tests and an adapter manifest → replay agreed Jira/GitHub fixtures → requires sandbox access and licences → pass on agreed operations, no duplicate writes and explicit failure handling. This extends existing integration work. [IN17](https://www.integratech.ae/icode-aws-ai-dev-deployment/)
3. **Safe action execution:** role controls are claimed → tool-specific approval behavior is unclear → document approval/rollback boundaries → exercise synthetic write and denial cases → depends on IAM and customer policy → pass only when every privileged action has an accountable approver and audit record. [IN09](https://www.integratech.ae/aws-genai-sdlc-iskaan-case-study/)
4. **Evidence portability:** named cases offer business metrics → buyers cannot reproduce attribution → create baseline/evaluation packs → repeat representative tasks before/after → requires customer-approved samples → pass against preregistered accuracy, latency and cost thresholds, not the published headline percentages. Existing Langfuse/CloudWatch should supply telemetry where available. [IN22](https://www.integratech.ae/aws-gen-ai-case-study-diglossia/)
